\subsection*{Algorithm}
The convolution of two signals, $x[n]$ and $h[n]$, is computationally intensive in the time domain. To accelerate this process, we utilize the Convolution Theorem, which states that convolution in the time domain corresponds to point-wise multiplication in the frequency domain.

\subsection*{Proposed Optimizations Hardware Architecture}
To achieve an area-efficient design, we propose a resource-sharing strategy that exploits the arithmetic similarities between the processing stages. 

\textbf{Resource Sharing Optimization:}
An analysis of the computational flow reveals that the Decimation-in-Frequency (DIF) FFT, the Decimation-in-Time (DIT) IFFT, and the point-wise multiplication steps all rely heavily on complex multiplication and addition/subtraction. Rather than instantiating separate hardware modules for each stage, we design a unified \textbf{Arithmetic Logic Unit (ALU)} capable of configuring itself as a Butterfly unit or a complex multiplier. This approach significantly reduces the silicon area, albeit at the cost of increased complexity in the Control Unit state machine.

\textbf{DIF-FFT and DIT-IFFT Pairing:}
A critical optimization in our design is the specific selection of FFT variants. We implement the forward transform using the \textbf{Radix-2 DIF} algorithm and the inverse transform using the \textbf{Radix-2 DIT} algorithm. 
\begin{itemize}
    \item The \textbf{DIF-FFT} produces output data in \textit{bit-reversed} order.
    \item The \textbf{DIT-IFFT} expects input data in \textit{bit-reversed} order to produce natural-order output.
\end{itemize}
By performing the intermediate point-wise multiplication directly on the bit-reversed data, we seamlessly connect the FFT output to the IFFT input. This eliminates the need for explicit data reordering buffers or logic, thereby reducing latency and memory addressing overhead.

\subsection*{Hardware Architecture}

Based on the proposed architecture, the hardware implementation consists of the following key components:

\begin{itemize}
    \item \textbf{RAM (Dual-port SRAM):} Provides on-chip storage for input sequences, intermediate spectral data ($X[k], Y[k]$), and the final output. It supports simultaneous read/write operations to maximize throughput.
    \item \textbf{Twiddle Factor ROM:} A lookup table storing the pre-computed trigonometric coefficients ($W_N^k$) required for the butterfly operations.
    \item \textbf{ALU (Reconfigurable Datapath):} The core computational engine. It executes complex additions and multiplications, dynamically switching roles between FFT Butterfly processing, spectral multiplication, and IFFT Butterfly processing.
    \item \textbf{Control Unit:} A Finite State Machine (FSM) that orchestrates the entire operation. It manages the complex addressing modes for bit-reversal/natural order access and controls the ALU's operating mode across the three processing stages.
\end{itemize}

\subsection{RAM}

\subsubsection{Overview}
The component is a synchronous, \textbf{True Dual-Port Random Access Memory (RAM)}. It facilitates two independent access ports (Port A and Port B), allowing simultaneous read or write operations to a shared memory space within a single clock domain.

\subsubsection{Parameters}
The design is fully parametrizable to support various storage requirements:

\begin{itemize}
    \item \textbf{DATA\_WIDTH}: Defines the width of the data bus (default: 64 bits).
    \item \textbf{MEM\_DEPTH}: Defines the total number of memory entries (default: 64 entries).
    \item \textbf{ADDR\_WIDTH}: Calculated automatically as $\lceil \log_2(\text{MEM\_DEPTH}) \rceil$ to ensure sufficient addressing bits are allocated.
\end{itemize}

\subsubsection{Functional Behavior}
The RAM operates under the following conditions:
\begin{itemize}
    \item \textbf{Synchronous Operation:} All memory transactions occur on the rising edge of \texttt{clk}.
    \item \textbf{Dual Access:} Port A and Port B operate independently and can be active simultaneously.
    \item \textbf{Read/Write Modes:}
    \begin{itemize}
        \item \textbf{Write Mode (\texttt{we = 1}):} The input data is written to the specified address.
        \item \textbf{Read Mode (\texttt{we = 0}):} The data at the specified address is registered into the output \texttt{q}.
    \end{itemize}
\end{itemize}
However, simultaneous read and write operations to the same address from different ports will lead to undefined behavior.

\subsection{Twiddle Factor ROM}
\subsubsection{Twiddle Factor ROM Architecture}

\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.9\linewidth]{images/rom_twiddle_arch.png}
    \caption{ROM-based twiddle factor storage scheme and reconstruction architecture}
    \label{fig:rom_twiddle_arch}
\end{figure}

As illustrated in Fig.~\ref{fig:rom_twiddle_arch}, the proposed twiddle factor generator employs a compressed ROM architecture that exploits the periodicity and symmetry properties of the complex exponential function.
Instead of storing all $N$ twiddle factors, only sine and cosine values corresponding to the first octant, i.e., the angular range $[0,\pi/4)$, are stored in ROM.
All remaining twiddle factors are reconstructed through address manipulation, sign inversion, and sine--cosine swapping.

\subsubsection{Twiddle Factor Compression Principle}

The twiddle factor used in FFT butterfly computation is defined as
\begin{equation}
W_N^k = e^{-j\frac{2\pi k}{N}} = \cos(\beta) - j\sin(\beta),
\label{eq:twiddle_def}
\end{equation}
where $\beta = \frac{2\pi k}{N}$ denotes the corresponding phase angle.

Due to the periodicity and symmetry of trigonometric functions, the sine and cosine values over the full interval $[0,2\pi)$ can be derived from values within the first octant $[0,\pi/4)$.
Consequently, only $N/8$ samples of sine and cosine values need to be stored in ROM, resulting in a significant reduction in memory requirements.

\subsubsection{ROM Addressing and Octant-Based Mapping}

As shown in Fig.~\ref{fig:rom_twiddle_arch}, the twiddle index is decomposed into two parts:
\begin{itemize}
    \item the most significant bits, which determine the octant of the input angle,
    \item the least significant bits, which specify the offset within the octant.
\end{itemize}

When the input angle lies within the first octant $[0,\pi/4)$, the offset bits are directly used as the ROM address.
For angles outside this range, the ROM address is generated through symmetry-based mirroring, while additional logic applies sign inversion and sine--cosine swapping to reconstruct the correct twiddle factor.

\subsubsection{Symmetrical Mapping of Twiddle Factors}

The mapping between the actual angle $\beta$ and the stored base angle in $[0,\pi/4)$ is summarized in Table~\ref{tab:twiddle_mapping}.
This table defines how sine and cosine values are reconstructed for all octants using symmetry operations.
\begin{table}[htbp]
\centering
\caption{Symmetrical mapping of twiddle factors}
\label{tab:twiddle_mapping}
\begin{tabular}{c|c|c}
\toprule
Angle range $\beta$ & Sine value & Cosine value \\
\midrule
$0 \sim \pi/4$ &
$-\sin(\beta)$ &
$\cos(\beta)$ \\

$\pi/4 \sim \pi/2$ &
$-\cos(\tfrac{\pi}{2}-\beta)$ &
$\sin(\tfrac{\pi}{2}-\beta)$ \\

$\pi/2 \sim 3\pi/4$ &
$-\cos(\beta-\tfrac{\pi}{2})$ &
$-\sin(\beta-\tfrac{\pi}{2})$ \\

$3\pi/4 \sim \pi$ &
$-\sin(\pi-\beta)$ &
$-\cos(\pi-\beta)$ \\

$\pi \sim 5\pi/4$ &
$\sin(\beta-\pi)$ &
$-\cos(\beta-\pi)$ \\

$5\pi/4 \sim 3\pi/2$ &
$\cos(\tfrac{3\pi}{2}-\beta)$ &
$-\sin(\tfrac{3\pi}{2}-\beta)$ \\

$3\pi/2 \sim 7\pi/4$ &
$\cos(\beta-\tfrac{3\pi}{2})$ &
$\sin(\beta-\tfrac{3\pi}{2})$ \\

$7\pi/4 \sim 2\pi$ &
$\sin(2\pi-\beta)$ &
$\cos(2\pi-\beta)$ \\
\bottomrule
\end{tabular}
\end{table}

Table~\ref{tab:twiddle_mapping} represents the core principle of the proposed ROM twiddle factor generator.
Rather than storing redundant trigonometric values across the full $2\pi$ range, the architecture reconstructs all required twiddle factors from a single base interval $[0,\pi/4)$.

The operations listed in the table—namely angle reflection, sine--cosine swapping, and sign inversion—are implemented using simple combinational logic.
As a result, the ROM size is reduced by a factor of eight, while maintaining exact trigonometric relationships and overall numerical accuracy.

The mapping rules defined in Table~\ref{tab:twiddle_mapping} are directly reflected in the ROM architecture shown in Fig.~\ref{fig:rom_twiddle_arch}.
Specifically, the address generation logic implements angle reflection, while the output multiplexers and sign inversion units apply the symmetry operations required to produce the final sine and cosine values.
